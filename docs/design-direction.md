# 실시간 세미나 보드 화면 디자인

세미나 운영자는 진행 상태를 빠르게 판단하고 참가자는 질문을 읽고 답변한다. 화면의 중심은 현재 질문과 참가자의 글이다. 운영 화면은 밀도 있는 도구로, 참가자와 발표 화면은 읽기 편한 공간으로 구성한다.

## 적용한 기준

[Taste Skill](https://github.com/Leonxlnx/taste-skill)의 중립적인 색 비중, 일관된 글자와 여백 체계, 기능을 설명하는 문구를 적용한다. [Hallmark](https://github.com/Nutlope/hallmark)의 앱 화면 지침에 따라 실제 작업을 먼저 배치하고, 반복되는 영문 소제목과 과도한 카드 중첩을 줄인다. 제공된 로고와 행사 키컬러는 운영자가 바꿀 수 있게 유지한다.

두 저장소의 디자인 원칙을 현재 시안에 맞춰 적용한 것이며, 전체 도구 모음을 전역 설치한 상태는 아니다. 홍보 페이지용 히어로, 사진 배치, 화면 높이 규칙은 행사 운영 화면에 적용하지 않는다. 사용자 요청인 우주 유영·별 반짝임과 이모지 반응은 제품 기능으로 유지한다.

## 화면별 구성

- 운영자: 로고와 행사명 왼쪽, View 선택 오른쪽. 답변 접수는 왼쪽 맨 위에 항상 보인다. 반응과 정렬, 질문과 안내, 이름과 익명, 행사 디자인은 접고 펼치는 그룹으로 나누고 접수 시간 설정을 별도 그룹으로 제공한다. 질문과 디자인의 적용 전 상태를 표시하고 익명 스위치는 즉시 적용한다. 공개 결과는 오른쪽, 보조 답변 관리는 접어서 볼 수 있다. 행사 기록 다운로드는 왼쪽 설정 하단에 둔다.
- View 1: 카드 테두리 대신 구분선으로 질문 목록을 구성한다. 이름과 상태는 작은 글씨, 답변 내용은 16px 이상으로 읽힌다. 운영자의 해결 체크는 행 오른쪽에 둔다. 해결된 질문은 목록 하단의 회색 영역에 표시한다.
- View 2: 반응 순위와 무관하게 새 글이 먼저 오는 보드다. 얇은 경계와 단정한 카드로 내용을 구분하고 이모지는 보조 조작으로 둔다.
- View 3: 어두운 우주 안에 이름과 글만 배치한다. 글은 기울이지 않는다. 기본 5색 테두리와 은은한 색 바탕으로 카드를 구분한다. 반응 조작을 없애고 모든 별의 반짝임, 유영 일시정지와 움직임 줄이기를 제공한다. 접수 상태는 한 곳에서 표시하며 제한 시간이 있으면 남은 시간도 함께 보인다.

## 디자인 값

기본 바탕은 따뜻한 중립색, 본문은 짙은 회색, 기본 키컬러는 짙은 녹색이다. 행사 키컬러는 주요 버튼, 초점과 선택 상태에 사용한다. 가상 행사의 이전 보라색 기본값은 새 기본값으로 전환하며 사용자가 지정한 다른 색은 유지한다. 로고가 없을 때는 행사 이름의 글자 표식을 사용한다.

본문과 조작은 IBM Plex Sans KR 및 시스템 대체 글꼴을 사용한다. 글꼴을 불러오지 못해도 기능은 유지된다. 일반 화면의 큰 그림자와 둥근 패널 반복을 줄이고 글의 크기, 간격, 구분선으로 위계를 만든다. 휴대폰에서는 설정과 공개 화면을 위아래로 배치한다.

## 검증 범위

정렬과 해결 복원, 운영자 권한 분기, 반응 상태, 움직임 제어는 DOM 모델을 이용해 확인한다. 다운로드 파일은 ZIP 무결성, XML 구조, 표와 필터, 날짜와 숫자의 자료형, 한국 시간 변환을 확인한다. 실제 브라우저의 화면·키보드 조작·애니메이션 및 다운로드 완료, Excel 앱에서의 열기는 별도 확인이 필요하다. 두 저장소의 브라우저 검사 도구가 통과했다는 주장은 하지 않는다.

## 최신 문구와 배치

공개 보기 이름은 목록형·카드형·우주형이다. 번호를 읽어야 이해되는 메뉴를 없애고 배치 방식으로 구분한다. 질문과 후기 어느 용도에도 쓸 수 있게 해결을 완료로 바꾸며, 체크박스 대신 `완료로 표시 / 완료 취소` 버튼으로 즉시 실행과 되돌리기를 드러낸다. 완료된 글은 회색과 완료 문구를 함께 보여준다. 결과 입력의 마지막 동작은 `답변 보내기`, 긴 글의 동작은 `글 전체 보기`다. 본문과 작성자 데이터는 문구 정리 과정에서 바꾸지 않는다.

UX Writing Skill(content-designer/ux-writing-skill)의 목적성·간결성·대화체·명확성 기준을 참고했다. 과학적 근거를 확인하지 않은 문장 길이별 이해도 수치는 제품 검증 근거로 사용하지 않았다. Unslop(heydamir/unslop)의 불필요한 배지 제거, 간격 정리와 보조 정보 절제 원칙을 적용하되 요청된 우주 효과와 행사 색상은 유지한다. 타이머는 안내 오른쪽의 테두리 없는 숫자로 표현하고 종료 상태는 크기를 키운다. 휴대폰은 별도 관리 탭 없이 설정 접기만 제공한다. 실제 브라우저 화면 검사나 사용자 이해도 검증이 끝났다는 의미는 아니다.

## 언어·밝기 조작과 글꼴 위계

언어 드롭다운은 `KOR | ENG` 직접 선택 버튼으로 교체한다. 현재 언어는 밑줄과 굵기로 구별하고 각 버튼에는 전체 언어 이름을 접근 가능한 이름으로 둔다. 화면 밝기는 해(왼쪽)와 달(오른쪽)을 넣은 단일 스위치로 바꾸고, 밝은 화면에서 왼쪽, 어두운 화면에서 오른쪽으로 손잡이가 움직인다. 키보드 기본 버튼 조작과 현재 상태를 제공하며 움직임 줄이기에서는 이동 애니메이션을 끈다. 운영자와 참가자에서 모두 같은 조작을 사용한다.

참가자 GNB에도 행사 키컬러를 적용한다. 글자색은 배경에 맞는 명도를 자동 선택하고 업로드 로고에는 지정된 밝거나 어두운 바탕을 유지한다. 환경 설정은 행사 이름과 보기 선택보다 시각적으로 낮은 위계에 놓는다. 설정은 큰 섹션 제목, 중간 그룹 제목, 입력 항목 제목, 보조 설명으로 크기·굵기·간격을 구분한다. 글꼴 미리보기에도 제목·본문·영문 보조문을 서로 다른 크기로 표시한다.

## GNB 밀도와 역할별 환경 설정

GNB를 행사 로고·이름 / 여유 공간 / 보기 선택 / 언어·밝기 묶음으로 구성한다. 전체 폭에 네 요소를 균등 분산시키지 않는다. 행사 이름은 16px, 보기 선택은 14px, 언어 선택은 11px로 차등 적용하고 터치 영역은 유지한다. 기본 패딩은 세로 12px, 가로 20px이며 환경 설정은 보기 선택과 24px 간격, 내부 8px 간격으로 묶는다. 작은 화면에서는 내용이 겹치지 않도록 행을 나눈다.

참가자의 언어와 화면 밝기는 각자의 읽기 선호이므로 선택권을 유지한다. 발표 화면에는 언어·밝기 조작을 모두 숨기고 운영자의 선택을 따른다. 현재 시안에서도 역할 전환 시 운영자/참가자 선호를 따로 기억하여 참가자의 변경이 발표 화면 설정을 바꾸지 않는다. 실제 여러 참가자의 기기별 저장과 배포는 향후 서버/클라이언트 구현 대상이다. 밝기 선호 관련 참고: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-color-scheme

## 미리보기와 첫 사용 설계

눈누 프리텐다드 페이지의 미리 써보기와 라이선스 분리를 참고하여 글꼴 견본을 제목이 있는 상자로 분리했다. 미리보기 제목·글꼴 이름·보조 안내는 기본 UI 글꼴로, 견본 본문만 선택 글꼴로 표시한다. 라이선스는 별도 접기 항목으로 남긴다. https://noonnu.cc/font_page/694

처음 사용자는 기능 설명을 외우기보다 실제 행사 준비를 진행한다. 샘플 전용 화면은 결과를 빠르게 이해하는 데 좋지만 실제 데이터와 혼동할 수 있다. 긴 안내 튜토리얼은 초기 부담이 크다. 세 단계 행사 준비를 기본으로, 샘플 둘러보기를 별도로 제공한다. 생성 직후에는 빈 상태와 다음 동작을 함께 안내한다. NN/g의 빈 상태 설계 원칙(상태 표시, 맥락 속 학습, 핵심 작업의 직접 경로)을 참고했다. https://www.nngroup.com/articles/empty-state-interface-design/

## 다크 모드의 화면 전환과 공감 위치

운영자·참가자·발표 화면 전환은 제품 창 밖의 투명한 검토 막대에 놓여 있었고, 제품만 다크 모드로 바뀌면 밝게 남은 외부 바탕 위에 밝은 버튼 글자가 표시될 수 있었다. 검토 막대에도 불투명한 제품 표면과 명시적 글자색을 적용하고, 현재 화면은 반전된 버튼과 체크 표시로 구분한다. 버튼 글자와 비선택 테두리·보조 글자의 기본 명암 대비를 라이트/다크 모두 계산해 4.5:1 이상으로 확인했다. 실제 브라우저 렌더링 확인과는 구별한다.

목록형의 공감 버튼은 왼쪽을 유지한다. 정렬의 핵심 지표인 숫자를 같은 세로축에 모아 비교할 수 있고 긴 질문에도 위치가 일정하다. 오른쪽은 읽은 뒤 반응하기에 자연스러울 수 있지만 목록형의 순위 비교보다 후속 반응을 강조한다. 이는 이 제품의 목표에 따른 설계 판단이며 모든 사용자에게 왼쪽이 더 편하다는 검증 결과가 아니다. 모바일은 기존 48px 투표 열과 44px 이상의 터치 영역을 유지한다. 편향 없는 의견 수집을 원하면 최신순과 반응 숨김을 사용할 수 있다.

## 종료 캐릭터와 재사용 가능한 디자인 참고

직접 구성한 ASCII 고양이를 상태 표시 근처에 작게 배치한다. 접수 중에는 두 프레임으로 달리고, 일시정지·마감 후에는 앉아 쉬며, 준비 중에는 앉아서 기다린다. 시간 종료 문구는 `접수를 마쳤어요 / All done!`로 바꾸고 오류처럼 보이는 빨간색 대신 기본 글자색을 쓴다. 남은 시간이 60초 이하일 때의 빨간 경고는 유지한다. 캐릭터는 장식으로 접근성 트리에서 제외하며 상태 문구는 그대로 제공한다. 움직임 줄이기에서는 달리기 프레임을 정지한다. 상태별 연동 로직은 검증했고 실제 프레임 재생은 아직 확인하지 않았다.

디자인 참고 후보(아직 라이브러리/일러스트를 가져와 적용한 것은 아님): Radix Themes(MIT, https://github.com/radix-ui/themes/blob/main/LICENSE), shadcn/ui(MIT, https://github.com/shadcn-ui/ui/blob/main/LICENSE.md), Open Doodles(CC0, https://www.opendoodles.com/about), Open Peeps(CC0, https://www.openpeeps.com/). 기본 UI는 Radix의 색·간격·위계를 참고하고 캐릭터는 현재 ASCII를 유지하는 방향을 추천한다. 실제 코드나 에셋을 반입할 때 해당 배포본 원문 라이선스와 저작권 고지를 함께 보관한다.
