# Google Sheets에 답변 기록하기

Hanmadi의 Sheets 연결은 **여러 휴대폰의 답변을 운영자의 시트에 기록하는 기능**입니다. 참가자 화면 미리보기의 답변 목록·공감·접수 상태·타이머 동기화와 운영자 인증은 아직 제공하지 않습니다. 전체 답변과 Excel 내려받기는 Google Sheets에서 이용하세요. Hanmadi의 Excel 버튼은 현재 화면의 답변만 내보냅니다.

## 처음 연결하기

시트 주소만으로는 외부 사이트가 내 시트에 답변을 쓸 수 없습니다. **Google Apps Script는 본인 Google 계정 안에서 Hanmadi의 답변을 시트에 옮겨 적는 연결 도구**입니다. 참가자에게 시트 편집 권한을 주는 대신, 이 연결 도구에 작성 권한을 승인하는 구조입니다.

앱은 초보자용으로 **시트 주소 입력 → 연결 코드 만들기·복사 → Google에서 권한 승인·배포 → 연결하고 테스트하기** 순서로 안내합니다. Google에 붙여 넣을 코드는 한 파일로 준비되며, 별도 HTML 파일을 만들 필요가 없습니다.

스크린별 설명은 [처음 연결하기 안내](google-sheets-test.md)를 따라주세요. 파일로 보관하는 선택지도 있지만 코드 복사만으로 설치할 수 있습니다. 여러 설문을 한 파일에 저장할 때는 답변 탭과 Google 연결 도구를 설문별로 나누세요.

## 기존 한글 열 9개를 사용하는 시트

아래 A:I 열은 이름·순서 그대로 지원합니다.

`제출 ID | 행사 ID | 부스 ID | 참가자 ID | 표시 이름 | 질문 ID | 질문 내용 | 답변 내용 | 제출 시각`

답변이 없는 이 형식의 탭에서 초기화를 실행하면 J:L에 다음 열이 추가됩니다. 기존 열이나 다른 탭은 삭제하지 않습니다. 이미 답변이 있는 9열 탭에는 자동 변환을 하지 않습니다. 기록을 보관하고 새 탭을 선택하세요.

| 열 | 용도 |
| --- | --- |
| `activity_status` | `submitted`: 실제 답변, `test`: 연결 테스트 |
| `client_id` | 같은 브라우저 세션을 구분하는 내부 값. 인증된 사용자 ID가 아님 |
| `payload_hash` | 같은 제출의 재시도인지 확인하는 내부 값. 수정하지 않음 |

전체 12개 열이 영문인 기본 형식도 지원합니다. 운영 중 헤더나 제출 ID·검증 값을 수정하지 마세요. `제출 시각`은 참가자 휴대폰 시계 대신 서버에서 생성한 UTC ISO 8601 문자열입니다.

## 기존 부스 인증 봇과 연결

- 봇은 **참가자 ID** 열로 사용자를 찾고, **activity_status가 `submitted`인 행만** 처리합니다.
- 표시 이름은 익명일 수 있으므로 인증에 사용하지 않습니다.
- 같은 참여자의 답변 제출이 여러 번 있을 수 있습니다. 메시지 중복 발송 방지는 봇에서도 `행사 ID + 부스 ID + 참가자 ID` 등 기존 인증 기준에 맞춰 처리하세요.
- 입력한 참가자 ID 자체가 본인 인증을 의미하지 않습니다. 다른 사람의 ID를 입력하지 못하게 해야 한다면, 기존 봇이 발급한 검증 가능한 참여 토큰을 검사하는 작업이 추가로 필요합니다.
- 이 수신기는 메신저를 직접 발송하지 않습니다.

## 접수 시작·마감과 질문 변경

초기 설정 후 Google 시트에 **`답변탭이름_설정`** 탭이 생깁니다. 기본은 **`hanmadi_설정`**입니다. **B2의 ‘답변 받기’ 체크를 켜면 접수 중, 끄면 마감**입니다. 시트의 체크를 바꾸는 것만으로 실제 수신기에 반영됩니다. 설정 탭을 지우거나 행사 코드 값을 바꾸지 마세요. 다른 이름의 기존 탭과 충돌하면 덮어쓰지 않고 오류를 표시합니다.

Hanmadi 화면의 ON/OFF나 타이머는 이 체크를 바꾸지 않습니다. 이미 열어둔 휴대폰에는 버튼이 열려 보일 수 있지만, 시트에서 마감한 수신기는 새 답변을 저장하지 않습니다. 기존 미확인 제출의 저장 확인은 마감 후에도 가능합니다.

개발 참고: 기존 2파일 설치도 동작합니다. 새 단일 파일 코드는 HTML 연결 코드를 내부에 포함합니다. 예전 수신기를 업데이트하지 않은 경우에는 이전의 스크립트 속성 `HANMADI_ACCEPTING` 방식이 유지됩니다. 새로 초기화하면 접수 상태를 체크박스에서 관리합니다.

현재 설치 1개는 질문 1개를 받습니다. 설치 파일에는 다운로드 당시의 질문·보기 방식·표시 설정이 담깁니다. 질문이 달라지면 새 행사와 탭, 별도 스크립트 프로젝트로 연결하세요. 기존 행사 설정을 변경해 재배포하려면 **배포 관리 → 수정 → 새 버전**이 필요합니다. **새 배포**를 만들면 URL도 바뀔 수 있으므로 QR을 다시 확인하세요.

## 여러 설문: 탭과 파일 중 선택

**같은 행사·주최자·열람 권한이면 1개 스프레드시트에 설문별 탭을 추천합니다.** 예: `hanmadi_booth_a`, `hanmadi_booth_b`, `hanmadi_talk`. 탭마다 별도 스크립트 프로젝트를 만들고 설치 파일에서 같은 시트 URL과 다른 탭 이름을 지정합니다. 한 스크립트 프로젝트를 수정해 여러 배포로 재사용하면 공용 스크립트 속성·초기화·종료 설정이 섞일 수 있어 이 방식은 권장하지 않습니다.

**주최자, 보관 기간, 개인정보 열람 권한이 다르면 파일도 분리하세요.** 탭 분리나 보호된 범위는 같은 파일 편집자 사이에서 비밀을 보장하는 방식이 아닙니다. 파일을 분리해도 같은 실행 계정의 Apps Script 한도가 증가하지는 않습니다.

## Apps Script 한도

2026-11-21 확인한 [Google 공식 한도](https://developers.google.com/apps-script/guides/services/quotas):

| 항목 | 개인 Google 계정 / Google Workspace |
| --- | --- |
| 동시 실행: 사용자당 | 30개 / 30개 |
| 동시 실행: 스크립트당 | 1,000개 / 1,000개 |
| 실행 시간: 1회 | 6분 / 6분 |

이는 **휴대폰 접속자 수가 아닌 실행 중인 요청 수**입니다. 소유자 권한으로 실행하므로 여러 설문의 요청이 같은 소유자에게 몰릴 수 있습니다. 500명이 한꺼번에 제출하는 상황을 보장하지 않습니다. 이 구현은 시트 쓰기와 중복 검사를 잠금으로 보호하므로 제출이 몰리면 대기·재시도가 발생합니다. 연결 확인용 프레임 로딩과 함수 호출도 실행을 사용합니다.

이 수신기는 `SpreadsheetApp`을 사용합니다. Sheets REST API의 분당 300회 제한을 이 구현의 정확한 처리량으로 해석하지 않습니다. 또한 트리거 일일 실행 시간(개인 90분)은 이 웹 앱 호출의 일일 한도를 뜻하지 않습니다. 서비스별 제한, 단시간 호출 제한과 계정 정책도 적용될 수 있으며 Google은 한도를 변경할 수 있습니다.

## 실패·재시도·개인정보

- Google에서 저장 확인을 받은 뒤에만 완료 화면을 표시합니다. 응답을 확인할 수 없는 `no-cors` 요청을 저장 성공으로 간주하지 않습니다.
- 결과 확인이 끊기면 같은 제출 ID로 다시 확인합니다. 이미 기록된 답변을 중복 추가하지 않습니다. 접수 마감 후에도 이전 제출의 확인은 가능합니다.
- 결과가 불확실한 동안에는 이전 제출 내용이 잠기며, 같은 내용을 다시 확인하도록 안내합니다. 임의로 새 ID를 발급해 중복 저장하지 않습니다.
- 미확인 제출은 해당 탭의 `sessionStorage`에 보관해 새로고침 후 재확인할 수 있습니다. 이 값에는 작성한 이름·답변·참가자 ID가 들어갈 수 있고, 탭을 닫으면 사라질 수 있습니다. 공유 기기에서는 제출 확인 후 탭을 닫으세요. 인터넷이 끊긴 채 탭을 닫아도 제출된다고 보장하지 않습니다.
- 공개 수신기에는 이름·답변 목록을 읽거나 시트를 수정·삭제하는 기능이 없습니다. Google 비밀번호·서비스 계정 키는 브라우저에 넣지 않습니다.
- 익명 이름 충돌은 시트 저장 시 다시 검사합니다. 참가자가 이미 사용 중인 이름이면 이름을 바꿔 재제출해야 합니다. 접속자마다 이름을 미리 예약하는 실시간 DB 기능은 아닙니다.

## 행사 전 확인

휴대폰 2대에서 서로 다른 참가자 ID로 제출 → 시트에 각 1행 저장 → 테스트 기록은 봇에서 무시 → 실제 제출자의 인증만 발송 → 마감 후 새 제출 거절 순서로 확인하세요. 공개 답변·참가자 ID를 보낼 동의 문구도 행사 목적에 맞게 확인하세요. 실제 Google 배포와 브라우저 통신, 기존 봇의 동작은 현장 리허설로 검증해야 합니다.

구현 검증: `node tests/google-sheets.test.cjs`, `node tests/google-sheets-ui.test.cjs`.
