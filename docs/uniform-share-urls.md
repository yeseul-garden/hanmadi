# 이전 20자리 공유 주소 구현 안내

> 이 문서는 이전 방식의 기록입니다. 현재 버전은 별도 공유 링크 저장소를 요구하지 않습니다. [URL 단축 옵션 안내](optional-url-shortening.md)를 참고하세요.

# 설문마다 같은 규칙으로 만드는 공유 주소

이제 특정 설문의 긴 링크를 파일에 하나씩 등록하지 않습니다. Supabase·Google Sheets 설문을 연결하면 공통 저장소에 연결 정보를 등록하고, 확인된 **20자리 코드**로 세 주소를 만듭니다.

```text
내 배포 주소/20자리코드/admin-page
내 배포 주소/20자리코드/participant-form
내 배포 주소/20자리코드/result
```

`https://yeseul-garden.github.io/hanmadi/`뿐 아니라, 다른 GitHub 계정·저장소 이름·도메인·하위 경로에서도 그 사이트의 배포 주소를 사용합니다. 주소에는 `#`를 붙이지 않습니다. 운영자 주소도 등록이 끝나면 주소창에 반영됩니다.

GitHub Pages에서는 함께 배포하는 `404.html`이 경로의 코드를 읽고 앱을 엽니다. 직접 접속·새로고침이 가능하지만 HTTP 응답 상태는 404입니다. HTTP 200 응답이 필요한 호스팅에서는 역할 경로를 `index.html`로 재작성하도록 설정하세요.

## 코드를 정하는 규칙

- **같은 설문:** 세 역할에 같은 코드를 씁니다. 화면 역할만 마지막 경로로 구분합니다.
- **다른 설문:** 사이트 주소, 저장 방식, Supabase 프로젝트 또는 Apps Script 연결 주소, 설문 고유값을 함께 사용합니다. 같은 프로젝트 안에서 여러 설문을 만들어도 코드가 구분됩니다.
- **정확히 20자리:** 위 값을 SHA-256으로 계산한 결과 중 120비트를 URL에 사용할 수 있는 문자로 바꿉니다. 영문 대·소문자, 숫자, `-`, `_`를 사용합니다.
- **키를 바꿔도 주소 유지:** 공개 키는 코드 계산에 넣지 않습니다. 허용된 등록자가 같은 코드의 공개 키를 갱신할 수 있습니다.
- **충돌 방지:** 데이터베이스에 전체 해시도 보관합니다. 코드가 겹쳐도 기존 설문의 연결을 덮어쓰지 않고 등록을 거절합니다.
- **주소는 권한이 아님:** 코드에 비밀번호·인증 토큰·Google 운영자 연결 키를 넣지 않습니다. `/admin-page`에서는 Supabase 운영자 로그인 또는 Google Sheets 운영자 연결 키를 별도로 확인합니다.

## 왜 공유 링크 저장소가 한 번 필요한가요?

20자리만 보고 원래의 긴 Supabase 주소·공개 키·Google 연결 주소를 알아낼 수는 없습니다. 방문자의 브라우저가 ‘이 코드는 어느 설문인가요?’를 조회할 곳이 필요합니다. GitHub Pages는 정적 파일을 제공하므로, 이 조회 정보는 Supabase의 별도 테이블에 보관합니다.

**사이트마다 한 번 설정합니다. 설문마다 GitHub에 설정 파일을 다시 올리는 방식이 아닙니다.** 답변 저장에 쓰는 Supabase 프로젝트를 그대로 이용해도 됩니다. 답변 저장소가 Google Sheets여도 이 공통 주소 저장소를 함께 사용합니다. 다른 사람이 프로젝트를 복사해 배포할 때는 자기 저장소로 설정합니다.

## 최초 설정 순서

1. 운영 화면에서 **공유 주소 설정 → 공유 링크 설정**을 엽니다.
2. 공유 링크를 보관할 Supabase 프로젝트 주소·공개용 키와 **그 프로젝트의 운영자 계정**으로 연결합니다. 이곳에 입력하는 비밀번호는 인증 후 지우며 설정 파일에는 넣지 않습니다.
3. **설치 SQL 다운로드**를 눌러 받은 파일 전체를 해당 프로젝트의 **SQL Editor**에서 실행합니다. 공유 주소 테이블·조회 함수와, 방금 확인한 운영자에게만 주소 등록을 허용하는 설정이 들어 있습니다. 기존 설문이나 답변은 지우지 않습니다.
4. **설정 파일 다운로드**로 받은 `share-config.json`를 사이트의 같은 파일과 교체해 배포합니다. 소스에서 빌드하는 경우 `public/share-config.json`를 바꿉니다. 이 파일에는 프로젝트 주소와 공개용 키만 있습니다.
5. 배포가 끝나면 페이지를 다시 엽니다. 답변 저장소를 연결한 뒤 **공유 주소 다시 준비**를 누릅니다. 이후 같은 사이트에서는 설문마다 자동으로 주소를 등록합니다.

업데이트 ZIP은 기존 `share-config.json`, `event-config.js`, 구형 `event-links.js`를 덮어쓰지 않습니다. 최초 설정 시에는 위 단계에서 받은 `share-config.json`을 별도로 추가하세요. 새로 설치하는 전체 ZIP에는 빈 설정 파일이 들어 있습니다.

답변 저장소와 공유 링크 저장소가 같은 Supabase 프로젝트이면 이미 연결한 운영자 세션을 사용합니다. 다른 프로젝트이거나 Google Sheets를 사용하는 경우, 공유 링크 설정에서 그 저장소의 운영자 계정을 확인합니다. 새 운영자를 추가할 때도 사이트 소유자가 설치 SQL로 해당 계정을 명시적으로 허용해야 합니다.

## 운영자 주소를 다시 열기

주소를 열면 **운영자 인증** 화면이 먼저 나옵니다. Supabase 설문은 해당 설문 소유자의 이메일·비밀번호, Google Sheets 설문은 해당 연결 코드의 운영자 연결 키를 입력합니다. 주소를 안다고 다른 설문을 관리할 수 없으며, 로그인 과정에서 새 설문을 추가로 만들지 않습니다.

## 설정 전·실패 시 동작

저장소 설정이나 주소 등록이 끝나지 않으면 QR·공유 주소가 준비되지 않았다는 안내를 표시합니다. 긴 주소를 몰래 대신 복사하거나, 다른 사람의 기기에서 열리지 않는 로컬 전용 코드를 만들지 않습니다. 등록이 지연된 경우 재시도해도 같은 설문은 같은 코드를 사용합니다.

이전에 발급한 `?e=…&v=…#sb=…`, `?e=…&v=…&gs=…`, 10자리 정적 매핑 링크는 읽는 기능을 유지합니다. **새로 발급하는 주소는 모두 위의 20자리 규칙을 사용**합니다. 기존 `event-links.js`는 구형 링크 호환용이며 새 설문 주소를 등록하는 데 쓰지 않습니다.

## 확인한 범위

로컬 PostgreSQL에서 반복 설치, 허용된 운영자의 등록, 방문자의 읽기 전용 조회, 소유자 외 수정 거절, 개인정보 제외, 코드 충돌 시 기존 주소 유지, JavaScript와 SQL의 코드 계산 일치를 확인합니다. UI 검사에는 운영자·참가자·발표 경로, 관리자 인증 전 진입 차단, 인증 후 같은 설문 열기, 기존 URL 읽기 호환성을 포함합니다.

실제 사이트에 쓰려면 **설치 SQL 실행과 `share-config.json` 배포가 한 번 필요**합니다. 이 변경이 사용자 Supabase에 자동으로 설치된 것은 아닙니다.
