# 세미나 실시간 참여 보드 개발 명세

행사 운영자가 질문과 공개 화면을 정하고 참가자는 QR로 접속해 이름과 답변을 제출한다. 같은 답변을 목록, 보드, 우주 화면으로 표시한다. 동시 참가자 500명 규모의 세미나를 목표로 이름 예약을 설계하며, 실제 지원 인원은 서버와 실시간 화면의 부하 검증 후 확정한다.

## 범위와 단계

현재 단계는 개발 명세와 상호작용 화면 시안이다. 시안의 데이터는 화면 안에서만 사용하는 가상 데이터다. 실제 QR 참여, 인증, 서버 저장, 기기 간 실시간 동기화는 구현 단계에 포함한다.

1. 행사 생성, 운영자 로그인, 참여 URL과 실제 QR 발급, 질문과 답변 저장.
2. 실시간 전파, 접수 제어, 질문 수정 및 새 질문 시작, 재연결.
3. View 1 정렬과 반응, 답변 관리, 발표 화면.
4. 로고와 키컬러, View 2, 전체 화면 전환 동기화.
5. View 3 이동과 순환, 가독성, 움직임 줄이기.
6. 권한과 부하 검증, 내보내기와 삭제, 설치 문서 및 공개 준비.

## 역할과 진입점

| 역할 | 진입점 | 권한과 표시 |
| --- | --- | --- |
| 운영자 | /admin/events/:id | 본인 행사 설정, 질문 관리, 접수와 View 제어, 답변 관리 |
| 참가자 | /e/:code | 공개된 현재 질문, 선택된 View, 본인 답변 작성, 허용된 반응 |
| 발표 화면 | /e/:code/present | 선택된 View, 질문, 로고, QR 표시. 관리 및 입력 기능 없음 |

최초 생성 시 View 1, 접수 OFF를 기본값으로 둔다. 참가자는 접속 당시의 운영자 선택을 즉시 따른다. 참가자에게 View 선택이나 관리 기능을 노출하지 않는다. 참여 코드는 운영 권한을 부여하지 않는다.

## 운영자 화면

상단 왼쪽은 로고와 행사명, 오른쪽은 목록 View 1 / 보드 View 2 / 우주 View 3 및 발표 화면 열기다. 본문 왼쪽은 설정, 오른쪽은 참가자 미리보기다. 답변 접수는 맨 위에 항상 노출하고, 나머지는 접수 시간, 반응과 정렬, 질문과 작성 안내, 이름과 익명 설정, 행사 디자인 다섯 그룹으로 접고 펼친다. 그룹을 접어도 반응과 표시 상태 및 현재 이름 방식을 요약해서 표시한다. 입력값을 바꾸면 적용 전 상태를 표시하고 변경사항 적용 버튼을 활성화한다. 참가자 미리보기 아래 답변 관리도 접어서 볼 수 있다. 행사 기록 다운로드는 왼쪽 설정 끝에 두며 긴 결과 목록 때문에 아래로 밀리지 않도록 설정 패널은 위쪽에 정렬한다.

- 행사 디자인: 행사명, 로고 업로드 및 제거, 키컬러, 로고 바탕색 선택.
- 질문: 질문 문구, 설명, 답변 입력 예시, 이름 입력란 제목과 예시, 이름 필수 여부.
- 진행: 답변 접수 ON/OFF, 반응 접수 ON/OFF, 이모지 표시 ON/OFF, 정렬 일시정지. 각각 별도 설정이며, 이모지를 숨기면 참가자는 새 반응을 입력할 수 없다. 우주 View에서는 반응 접수와 표시가 항상 비활성이다.
- 답변 관리: 숨김 및 복원, 고정 및 해제, 삭제, View 1의 답변 완료, 이전 질문 조회.
- 질문과 디자인 편집은 초안으로 보관 후 적용한다. View 선택과 접수 전환은 즉시 반영하되 서버 승인 전에는 반영 중 상태로 표시한다. 실패 시 실제 상태로 복구하고 안내한다.
- 로고는 비율을 유지하고 밝고 어두운 배경 모두에서 확인한다. SVG는 정제 없이 직접 렌더링하지 않는다. 최초 지원 형식은 PNG, JPEG, WebP이며 상한은 2MB를 제안한다.

## 참가자 화면

위에서부터 로고와 행사명, 접수 상태, 현재 질문과 작성 안내, 답변 작성 버튼, 선택된 결과 View를 배치한다. 답변 작성 버튼은 결과 목록 위에 두어 게시물 수와 관계없이 같은 위치에서 접근하도록 한다. 참가자 화면에서는 가로 폭을 채운 버튼 아래에 공개 안내를 표시하고, 구분선 아래에서 기존 답변을 보여준다. 입력 시 모바일은 하단 시트, 넓은 화면은 대화상자로 연다. 발표 화면에는 답변 작성 버튼을 표시하지 않는다.

- 필드: 운영자가 지정한 이름 입력란, 현재 질문의 답변. 이름 50자, 답변 1,000자를 초기 상한으로 제안한다.
- 공개 안내: 이름과 답변이 행사 화면에 공개됨을 제출 전에 표시한다.
- 이름 필수는 기본 ON. 익명 모드에서는 닉네임을 자동 입력한다. 이름 필수가 OFF인 일반 모드에서 공란으로 제출한 경우에도 중복 없는 동물 닉네임을 할당한다.
- 여러 답변 제출은 기본 허용하고, 연속 제출은 서버에서 제한한다.
- 제출 중 버튼 중복 클릭을 막고, 성공 응답 후 입력을 비운다. 실패 시 입력을 유지한다.
- 접수 마감 시 입력은 유지하고 제출을 막는다. 재개 시 같은 질문이면 다시 제출할 수 있다.
- View 전환은 열린 입력창과 초안에 영향을 주지 않는다.
- 서버 저장 전에 낙관적으로 성공 표시하지 않는다. 긴 텍스트는 줄바꿈하며 목록에서는 전문 펼치기를 지원한다.

## 접수 상태와 제한 시간

공개 화면의 접수 상태는 하나만 표시한다. 운영자 미리보기, 참가자 및 발표 화면에 공통으로 표시하며 접수 중에는 글자가 천천히 밝아졌다 어두워진다. 중복되던 공개 화면 제목 옆 상태는 제거한다. 움직임 줄이기 환경에서는 깜빡임 없이 상태 글자와 색으로 구분한다.

운영자는 ‘접수 시간’ 그룹에서 제한 시간 사용과 1~180분 사이 정수 시간을 설정한다. 기본값은 제한 없음, 제안 시간은 5분이다. 접수 중에 제한 시간을 켜면 지정 시간으로 즉시 시작한다. 분을 수정하는 것만으로 진행 중 타이머를 바꾸지 않으며 ‘설정 시간으로 접수 시작’을 누르면 해당 시간으로 재시작한다. 접수 마감 상태에서 시간을 설정해도 버튼을 누르기 전에는 자동으로 접수를 열지 않는다.

남은 시간은 공통 공개 화면에 분과 초로 표시한다. 마감 시각에서 현재 시각을 빼 계산하며 매번 1초씩 차감해 누적 오차를 만들지 않는다. 60초 이하에서는 남은 시간을 빨간색으로 천천히 깜빡인다. 0초가 되면 답변 접수를 자동으로 닫고 00:00 및 종료 상태를 표시한다. 작성 중인 본문과 이름은 유지하며 제출 순간에도 마감 여부를 재확인한다. 좋아요 등 반응 접수는 기존의 독립 설정을 따른다.

수동 마감은 타이머를 해제한다. 제한 시간이 켜진 상태에서 다시 접수 ON을 누르면 설정된 시간부터 새로 시작한다. 시간 제한을 끄면 접수 상태는 유지하고 마감 시각만 제거한다. 새 질문 시작 시 이전 타이머를 제거하고 접수 OFF로 둔다. View 전환이나 우주 애니메이션 일시정지는 접수 시간을 멈추지 않는다.

시안은 같은 화면 상태에서 절대 마감 시각으로 동작한다. 실제 서비스에서는 서버가 마감 시각과 현재 서버 시각을 배포하고 참가자는 시각 차이를 보정해 표시한다. 서버가 제출 트랜잭션에서 접수 상태, 질문 버전과 마감 시각을 최종 검증한다. 화면의 카운트다운만으로 실제 제출 권한을 판정하지 않는다.

## 답변 작성 안내

운영자 화면의 질문 입력란 바로 아래에 선택 입력인 ‘답변 작성 안내’를 둔다. 하나의 여러 줄 입력란에서 어떤 내용을 쓰면 되는지 설명하고, 필요하면 예시 답변 1~2개를 함께 적는다. 최대 1,500자로 제한하며 ‘변경사항 적용’을 눌러 공개한다.

안내는 현재 질문 아래와 참가자의 답변 작성창 안에 같은 내용으로 표시한다. 운영자 미리보기, 참가자 화면, 발표 화면 및 세 View에 공통 적용한다. 줄바꿈을 유지하고 HTML은 실행하지 않는다. 공백만 입력하거나 내용을 지우면 안내 영역 전체를 숨긴다. 답변 필드에 예시를 실제 답변처럼 채우지 않는다.

새 질문 시작창에도 별도의 작성 안내 입력란을 제공한다. 새 질문의 안내는 빈 상태로 시작하며 이전 안내를 자동으로 가져오지 않는다. 질문별 안내를 함께 보관한다. 작성 중 안내가 바뀌면 답변 초안과 닉네임은 유지하며, 변경된 안내를 확인한 후 제출하게 한다.

## 익명 이름과 중복 방지

운영자의 ‘이름과 익명 설정’ 그룹에 ‘익명으로 받기’ 스위치를 두며 기본값은 OFF다. 익명 스위치는 누르는 즉시 실제 참가자 설정에 반영한다. 질문과 안내, 일반 이름 입력란 및 행사 디자인은 별도의 변경사항 적용을 사용한다. ON이면 참가자에게 ‘닉네임’ 제목을 표시하고 형용사와 동물을 조합한 실제 값을 이름 필드에 채운다. placeholder가 아니므로 참가자가 직접 수정할 수 있다. 일반 모드의 이름 제목·예시·필수 설정은 보존하고 익명 ON 동안 편집을 비활성화한다. OFF로 되돌리면 원래 설정을 복원한다.

형용사 72개와 동물 100개로 숫자 접미사 없이 7,200개 이름을 만든다. 랜덤 시작점부터 사용 가능한 조합을 찾아 예약한다. 500명에게 같은 시작 후보가 주어지는 경우도 서로 다른 이름을 배정한다. 조합 수만으로 중복 방지를 보장하지 않으며 행사별 예약 저장소에서 이름 소유자를 확인한다.

자동 닉네임과 직접 입력한 이름 모두 같은 행사 안에서 중복을 막는다. 앞뒤 및 내부 공백, 대소문자, 전각 문자와 보이지 않는 구분 문자의 차이만 있는 이름도 같은 것으로 판정한다. 이름은 참가자 세션에 연결한다. 같은 참가자는 여러 질문에서 자신의 이름을 재사용할 수 있으며 다른 참가자는 사용할 수 없다. 숨김·보관된 글의 이름과 변경 전 이름도 행사 종료까지 원래 참가자의 예약으로 보관한다. 익명 모드 전환은 기존 답변의 작성자 이름을 소급해서 바꾸지 않는다.

입력 중 이미 예약된 이름이면 필드 아래에 안내하며, 제출 시 다시 검사해 중복 등록을 차단한다. 별명 수정 후에도 실명이나 식별 정보를 필수로 수집하지 않는다. 익명 설정이 바뀌어 작성 중 실명 필드가 닉네임으로 전환되면 본문은 보존하고 이름을 자동 별명으로 교체한다. 닉네임을 수정해 제출하면 다음 답변에도 같은 이름을 기본으로 사용한다.

실제 서버는 QR 참여 세션을 발급한 뒤 이름을 예약하고 결과를 반환한다. 행사와 참가자 ID는 검증된 세션에서 가져오며 클라이언트가 보낸 소유자 ID를 신뢰하지 않는다. 이름 키에 행사별 UNIQUE 제약을 두고 INSERT 충돌 시 다른 조합을 다시 예약한다. 사용자 지정 이름이 충돌하면 HTTP 409로 응답하고 작성 내용을 유지한다. 같은 참가자의 재시도는 같은 이름을 반환하도록 처리한다. 예약과 질문·접수 상태 검증 및 답변 저장은 서버 트랜잭션 안에서 처리한다.

참조 구현은 database/name-reservations.sql 및 database/name-pool-seed.sql에 있다. PUBLIC 접근은 차단하고 향후 검증된 백엔드 역할에만 권한을 부여한다. 기존 데이터가 생긴 뒤 도입하는 경우에는 이름 정규화와 중복 정리 후 예약 데이터를 채운다. [PostgreSQL 고유성 검사](https://www.postgresql.org/docs/current/index-unique-checks.html), [Unicode 정규화](https://www.postgresql.org/docs/15/functions-string.html)를 기준으로 한다.

현재 시안은 화면 안의 예약 저장소로 동작하며 서버는 연결되지 않았다. 500개 참가자 키를 이용한 이름 생성과 충돌 처리는 검증했지만, 실제 500개 동시 네트워크 요청이나 PostgreSQL 동시성·성능 시험을 수행한 상태는 아니다. 서버 연결 후 동일 후보 충돌, 사용자 지정 이름 동시 요청, 재접속, 다른 행사에서의 동일 이름 사용 및 예약 풀 소진을 검증해야 한다.

## 질문 변경 정책

현재 질문 수정은 오타나 안내 변경에 사용하며 질문 ID와 답변을 유지한다. 수정 시 질문 버전을 올린다. 새 질문 시작은 새 ID를 생성하고 이전 질문과 답변을 보관하며 접수 OFF로 시작한다. View와 행사 브랜딩은 유지한다.

참가자 초안은 질문 ID와 버전에 연결한다. 제출 요청에도 두 값을 포함한다. 작성 중 질문 ID 또는 버전이 바뀌면 초안을 보존하고 변경된 질문을 확인한 후 다시 제출하게 한다. 과거 질문의 답변을 새 질문으로 자동 이동하지 않는다. 이름 입력란 제목 변경은 기존 참가자 이름을 수정하지 않는다. 기존 답변의 이름 입력란 제목은 제출 당시 값으로 기록한다.

예시 A: 이름 제목 ‘영문 ID’, 질문 ‘AI Self-Learning 페이지를 더 사람들이 잘 쓰게 만들려면 어떤 부분을 개선해볼 수 있을까요?’

예시 B: 이름 제목 ‘한글 성함’, 질문 ‘오늘 세미나를 진행한 연사에게 궁금한 점이 있다면 질문해주세요. 구체적일수록 좋습니다.’

## View별 동작

| View | 정렬 및 표시 | 반응과 제어 |
| --- | --- | --- |
| 목록 | 미해결 질문은 운영자 고정 먼저, 다음 👍 상위 3개, 나머지는 최신순. 의견 수집 모드는 고정 후 최신순. 해결된 질문은 별도 묶음으로 항상 맨 아래. 각 영역 간 중복 제거. 동점은 작성시각 내림차순, 마지막은 ID로 결정 | 운영자만 해결 체크 가능. 해결된 행은 회색으로 표시하고 반응을 비활성화. 👍만 인기 순위에 반영. 정렬 일시정지는 구현 단계에서 추가 |
| 보드 | 가장 나중에 제출한 답변이 첫 번째 카드. 반응 수나 고정 여부는 보드 순서에 영향 없음. 신규 답변은 묶어 반영해 읽는 중 재배치를 줄임 | 반응 수가 있는 이모지만 카드 하단에 표시. 옆의 ＋에서 👍 ❤️ 👏 💡 🎉 👀를 선택해 추가. 전문 펼치기 |
| 우주 | 같은 공개 답변을 2D 레이어로 표시. 서로 다른 주기의 가로·세로 곡선 이동, 별 배경 이동 및 별마다 다른 주기의 반짝임으로 유영 표현. 한 화면 표시량 제한과 순환은 구현 단계에서 추가 | 이름과 답변만 표시. 참가자·발표·전문 보기 모두 반응 버튼과 수치를 숨기고 반응 입력을 차단. 전체 일시정지, 카드에 마우스나 키보드 포커스가 오면 해당 카드 정지 |

운영자 미리보기, 참가자, 발표 화면은 동일한 공개 답변 목록과 정렬 계산을 공유한다. 발표 화면에서는 이름과 답변, 표시가 허용된 반응 수치를 표시하되 반응을 누르거나 추가하는 기능은 제공하지 않는다. 관리 목록도 현재 공개 화면의 순서를 따르며 숨긴 답변은 마지막에 별도 상태로 표시한다. 이전 질문을 관리할 때는 그 질문의 답변만 조회한다.

View 1은 👍를 항상 기본 표시해 공감의 의미와 순위 기준을 분명하게 하고, 다른 이모지는 반응 수가 있을 때만 표시한다. View 2는 사용된 반응만 표시하고 처음에는 ＋만 보일 수 있다. 목록과 보드 모두 반응 옆의 ＋로 여섯 종류 중 반응을 추가한다. 여러 종류를 선택할 수 있으며 같은 반응을 다시 누르면 본인 반응만 취소된다. 반응 수가 0이 되면 해당 이모지를 제거하되 View 1의 기본 👍는 유지한다. 반응 선택창에는 사용할 수 있는 여섯 종류를 항상 표시한다. 👍 이외의 이모지는 View 1에서도 정렬에 영향을 주지 않는다.

운영자의 이모지 표시 OFF는 목록과 보드의 버튼, 수치와 ＋를 숨긴다. 반응 접수 OFF는 기존 수치를 유지하면서 새 반응과 취소를 막는다. 표시를 다시 켜거나 View를 변경해도 기존 반응은 보존한다. 이모지 표시 OFF 중에도 View 1의 기존 공감 순위는 유지하며 운영자에게 이를 안내한다. 공감 순위 자체를 사용하지 않으려면 최신순으로 전환한다. 서버 구현에서도 반응 저장 시 현재 View, 표시 여부와 접수 여부를 검증한다.

질문 선정에서는 👍를 ‘나도 이 질문의 답을 듣고 싶다’로 해석한다. 개선 의견 수집에서는 ‘나도 공감한다’로 해석하며 찬성 표가 적다고 가치가 낮은 의견으로 판단하지 않는다. 초기 노출의 영향을 줄이려면 의견을 모으는 동안 최신순을 사용하고 논의할 내용을 고를 때 인기 정렬로 전환하는 운영 방식을 제안한다. 카드 내 다양한 감정 반응은 순위에 합산하지 않는다.

숨김 또는 삭제 답변은 모든 View에서 제거한다. 숨김은 복원 가능하고 삭제는 별도 확인 후 수행한다. 해결 체크는 View 1 카드의 운영자 전용 체크박스다. 체크하면 해결 완료 시각을 기록하고 하단 ‘해결된 질문’ 영역으로 이동하며 회색 표시와 반응 비활성 상태를 세 역할 화면에 동일하게 적용한다. 다시 누르면 완료 시각과 해결 상태를 해제하고 현재 정렬 방식, 공감 수, 고정 상태 및 등록 시각에 따라 위치를 다시 계산한다. 원래 반응 수와 고정 여부는 변경하지 않는다. 새 글이나 반응 때문에 복원 시점의 실제 순위는 이전 행 번호와 다를 수 있다. View 2와 3에서는 해결 여부로 순서나 표현을 바꾸지 않는다. 애니메이션 좌표는 기기마다 계산하며 서버로 계속 전송하지 않는다. 움직임 줄이기 환경에서는 정적 배치를 기본으로 제공하고, 참가자가 현재 화면에서 직접 움직임을 켤 수 있다.

## 행사 기록 다운로드

운영자 설정 왼쪽 영역 맨 아래에 ‘행사 기록’과 ‘Excel 파일 내려받기’를 둔다. 진행 제어와 떨어뜨려 종료 후 정리 작업임을 구분한다. 참가자와 발표 화면에는 표시하지 않는다. 접수 중에도 현재 시점의 기록을 내려받을 수 있으며 접수 상태를 바꾸지 않는다.

실제 .xlsx 파일을 브라우저 안에서 생성한다. ‘질문 기록’ 시트는 등록된 답변 한 건당 한 행이며 이전 질문과 숨긴 답변을 포함한다. ‘질문 목록’ 시트는 제출이 없는 운영자 질문도 포함하고 질문 번호, 질문 문구, 등록 수, 답변 완료 수와 현재·보관 상태를 기록한다. 첫 행 고정, 필터, 줄바꿈 및 열 너비를 적용한다.

기록 열은 운영자 질문, 질문자, 질문 내용, 질문 올린 시간, 여섯 이모지별 개수, 답변 유무, 공개 상태, 질문 번호, 제출 당시 이름 입력란 제목, 답변 완료 시간이다. 시간은 한국 시간으로 표시하는 정렬 가능한 날짜 값, 이모지 개수는 숫자로 저장한다. ‘답변 유무’는 운영자의 해결 체크 상태이며 연사가 말한 답변 전문은 별도로 기록하지 않는다. 사용자 글은 수식으로 실행되지 않는 문자열로 저장한다. 파일명은 행사명과 다운로드 날짜를 사용한다. 이모지 표시나 반응 접수 OFF에서도 기존 반응 수는 내보낸다.

현재 시안에서는 가상 데이터와 시안 안에서 제출한 내용만 파일에 들어간다. 실제 서버 구현에서는 행사 소유자 권한을 확인하고 전체 기록을 조회한다. 영구 삭제한 기록은 내보내기에 포함하지 않는다.

우주 시안은 브라우저 기본 Web Animations API로 곡선 경로와 별 반짝임을 재생한다. 반짝이지 않던 고정 배경 별 무늬를 제거하고, 표시되는 모든 별을 서로 다른 주기의 실제 반짝임 요소로 생성한다. 별 밀도는 화면 면적에 맞추되 60~140개로 제한한다. 별의 밝기는 서로 다른 주기로 천천히 변한다. 화면 전환과 크기 변경 시 기존 재생 위치를 보존하며 불필요한 애니메이션은 취소한다. 상세 답변을 읽는 동안과 페이지가 보이지 않을 때는 일시정지한다. 움직임 줄이기는 카드 이동과 별 반짝임에 함께 적용한다. 외부 애니메이션 의존성은 추가하지 않는다. 참고: [브라우저 애니메이션 API](https://developer.mozilla.org/en-US/docs/Web/API/Element/animate), [Motion 라이브러리 검토](https://motion.dev/docs/animate).

## 우주 카드 색상

우주 View의 기본 색상은 코랄, 앰버, 민트, 블루, 로즈의 5색이다. 색은 답변 ID를 기준으로 안정적으로 배정하며 글이 추가되거나 정렬을 바꿔도 기존 글의 색을 바꾸지 않는다. 테두리는 각 색을 선명하게 쓰고 카드 바탕은 같은 색을 소량 섞는다. 이름과 본문은 밝은 중립색을 유지한다. 색은 순위나 투표 결과를 의미하지 않는다.

운영자 ‘행사 디자인’에서 기본 행성 5색, 행사 키컬러의 명도 변형 5색, 직접 지정한 5색을 선택할 수 있다. 기본색에 행사 키컬러가 임의로 덮어씌워지지 않으며 키컬러 모드를 선택했을 때만 연동한다. 키컬러는 HEX 입력과 색상 선택기를 서로 동기화한다. 직접 지정 모드에서는 다섯 색상 선택기를 각각 바꿀 수 있다. 색상과 모드 변경은 ‘변경사항 적용’ 후 공개한다.

## 브랜드 적용

키컬러는 버튼, 선택 상태, 강조선, 신규 답변 효과, 우주 성운 일부에 사용한다. 본문 가독성을 우선하며 입력된 키컬러와 버튼 글자색 조합은 대비를 계산해 보정한다. 로고는 왼쪽 위에 고정된 영역 안에서 원래 비율로 표시하고 행사명은 함께 제공한다. 흰색 로고에는 어두운 받침을 선택할 수 있게 한다. 시스템 이름과 행사명은 분리한다.

## 데이터와 동기화

Event는 소유자, 공개 코드, 행사명, 로고 위치, 키컬러, 현재 질문 ID, 활성 View, 표시 설정과 상태 버전을 갖는다. Prompt는 행사 ID, 질문, 설명, 이름 제목과 필수 여부, 입력 예시, 질문 버전, 접수 상태, 반응 상태와 보관 시각을 갖는다. Participant는 행사별 익명 식별자를 갖는다. Response는 질문 ID, 참가자 ID, 제출 당시 이름과 이름 제목, 내용, 생성시각, 공개 상태, 고정 및 완료 상태와 요청 중복 방지 키를 갖는다. Reaction은 답변 ID, 참가자 ID, 종류를 갖고 이 조합에 유일 제약을 둔다.

초기 상태는 서버에서 조회하고 이벤트를 구독한다. 조회와 구독 사이 누락을 막기 위해 구독 완료 후 상태를 다시 확인한다. 서버 이벤트에는 버전을 포함하고 오래된 상태는 적용하지 않는다. 재연결 시 스냅샷을 다시 받으며 ID로 중복 제거한다. 제출 재시도에는 동일한 중복 방지 키를 사용한다. 접수와 질문 버전 검증 및 답변 저장은 하나의 원자적 처리로 묶는다.

익명 식별자는 사람 한 명을 보증하지 않는다. 중복 반응 제한은 익명 세션 기준이며 서버에서 제한한다. 브라우저가 보낸 반응 총수를 신뢰하지 않는다. 승인 대기나 숨김 데이터는 공개 구독 채널에도 포함하지 않는다. 서버 비밀키는 참가자 코드에 포함하지 않는다.

## 구현 경계

React 기반 UI와 서버 API, PostgreSQL을 기본 구조로 제안하며, 실시간 저장소 연결은 별도 계층으로 분리한다. 화면 컴포넌트는 인증이나 데이터베이스를 직접 다루지 않고 동일한 답변 모델을 받는다. 구체적인 프레임워크 버전과 호스팅은 실제 구현 시작 시 공식 문서와 운영 조건을 확인해 고정한다.

## 첫 버전 완료 조건

- 서로 다른 두 기기에서 제출한 답변이 운영자와 참가자에게 보인다.
- 접수 마감과 질문 교체 직전의 요청도 서버에서 올바르게 판정한다.
- 참가자는 다른 행사 데이터와 운영 기능에 접근할 수 없다.
- 같은 요청 재시도나 반응 연타로 중복 기록이 생기지 않는다.
- 새로고침과 연결 복구 후 저장된 답변 및 현재 설정을 복원한다.
- 긴 한국어와 영문 ID, 긴 질문, 320px 휴대폰 화면에서 핵심 조작이 가능하다.
- View 전환과 접수 종료로 작성 중 초안이 사라지지 않는다.
- 목표 인원의 동시 참여를 시험하고 측정한 결과에 따라 지원 범위를 문서화한다.

## 공개 준비

실제 사용자 정보가 없는 데모 행사, 환경변수 예제, 설치 및 데이터베이스 갱신 절차, 권한 설정, 기여 안내를 제공한다. 라이선스는 공개 전 선택하며 임의로 확정하지 않는다. 인증정보는 추적에서 제외한다. 실제 행사 내보내기 파일과 업로드 로고는 저장소에 포함하지 않는다.

## 최신 화면·문구 기준 (2026-11-21)

이 절은 앞선 시안의 View 번호, 인기 영역, 해결 체크박스, 시간 배너 및 우주 반응 제한 설명을 대체한다.

- 공개 보기 이름은 `목록형 / 카드형 / 우주형`, 영어는 `List / Cards / Space`다. 내부 식별자 list/board/space는 유지한다. 내용이 질문인지 후기인지에 종속되지 않는 배치 방식으로 이름을 정한다.
- 목록형은 공감순 또는 최신순의 단일 목록이다. 인기 배지나 상위 3개 구역을 만들지 않는다. 운영자에게만 `완료로 표시` 버튼을 제공한다. 표시한 글은 회색으로 맨 아래에 놓고 반응을 막는다. `완료 취소`로 현재 공감·고정·최신 정렬에 복귀한다. 다른 역할에는 완료 상태만 보인다. 완료는 운영자가 해당 글을 다뤘다는 표시이며 내용에 동의하거나 문제가 해결됐다는 의미를 강제하지 않는다.
- 답변 작성 버튼은 결과보다 위에 둔다. 질문 아래에는 작성 안내를 왼쪽, 접수 상태와 남은 시간을 오른쪽에 놓는다. 별도 시간 상자를 만들지 않는다. 종료 시 숫자는 숨기고 `접수 시간 종료`를 크게 표시한다. 시간은 분·초로 설정하며 60초 이하에서 빨간색 점멸, 0초에서 자동 마감한다.
- 반응 표시는 목록형·카드형 기본 켜짐, 우주형 기본 꺼짐이다. 보기별 설정을 독립적으로 바꿀 수 있다. 우주형도 켜면 반응 조작이 가능하며 전체 반응 접수 스위치를 따른다.
- 모바일 운영자 화면은 진행·설정·미리보기 탭을 만들지 않는다. 한 페이지에서 진행 조작, 접힌 행사 설정, 공개 결과를 순서대로 제공한다. 참가자 작성창은 작은 화면에서 아래쪽 시트로 열린다.
- 한국어가 기본이며 운영자와 참가자 상단에서 English를 선택할 수 있다. 사용자 작성 질문·안내·이름·답변은 원문을 유지한다.
- 밝은 화면과 Monokai 기반 어두운 화면을 제공한다. 직접 지정한 키컬러는 상단 내비게이션과 주요 조작에 반영한다.
- 한글 글꼴 네 가지(IBM Plex Sans KR, Pretendard, Noto Sans KR, Noto Serif KR) 다음에 영문 네 가지(Inter, DM Sans, Manrope, Source Sans 3)를 제공한다. 라이선스는 licenses/fonts에 보관한다. 직접 추가한 글꼴은 현재 시안의 세션에서만 사용하며 아직 다른 참가자에게 배포되지 않는다.

현재 결과물은 가상 데이터를 사용하는 단일 화면 시안이다. 실제 행사 서버, 여러 기기 동기화, 폰트 배포 및 실사용 부하 검증은 아직 포함하지 않는다.

상단 환경 선택은 드롭다운 대신 `KOR | ENG` 버튼과 해·달 슬라이드 스위치를 사용한다. 한국어가 기본이며 사용자 원문은 번역하지 않는다. 참가자 GNB는 운영자 지정 키컬러와 대비되는 글자색을 사용한다. 밝기 전환은 행사 키컬러를 유지한다. 위 조작의 양방향 전환과 접근성 상태 동기화는 DOM 모델에서 검증했다. 실제 모바일 브라우저 배치와 아이콘 렌더링은 별도 확인이 필요하다.

## 예시 콘텐츠의 언어

English를 선택하면 기본 질문, 작성 안내의 두 예시, 네 개의 가상 답변, 기본 이름란 제목, 글꼴 미리보기, 새 질문 입력란의 예시 문구도 영어로 표시한다. KOR로 돌아오면 한글 예시를 복원한다. 미리 정의된 예시에만 대응 문구를 제공하며 운영자가 수정한 질문·안내, 참가자가 작성한 답변 및 저장 전 초안은 바꾸지 않는다. 원본 데이터는 표시 언어 전환으로 덮어쓰지 않는다.

한글 기본 질문은 `더 많은 사람이 AI Self-Learning 페이지를 편리하게 이용하려면 무엇을 개선하면 좋을까요?`, 새 질문 예시는 `오늘 연사에게 궁금한 점을 적어 주세요. 어떤 내용이 궁금한지 구체적으로 알려 주세요.`로 정리한다. 입력란과 질문·안내는 한글 단어 단위로 줄을 바꾸고 긴 단어는 넘치지 않도록 처리한다. 영어는 일반 영문 줄바꿈을 사용한다.

GNB는 왼쪽 행사 식별, 오른쪽 보기 선택과 환경 설정 묶음으로 정리한다. 참가자 언어·밝기 선택은 개인 환경 설정으로 유지한다. 발표 화면에는 선택 조작을 노출하지 않고 운영자의 언어·밝기를 따른다. 시안의 역할별 선호 전환·복원, 발표 화면의 환경 변경 방지는 DOM 모델에서 확인했다. 실제 브라우저의 GNB 배치 검사는 아직 수행하지 않았다.

## 첫 사용과 행사 준비 순서

최초 화면은 가상 답변이 채워진 운영 화면 대신 시작 화면이다. `새 행사 만들기`를 주 동작, `샘플 행사 둘러보기`를 보조 동작으로 제공한다. 샘플은 가상 답변임을 표시하고 `내 행사 만들기`로 전환할 수 있다.

행사 준비는 1) 행사명과 선택 로고·키컬러, 2) 질문과 선택 작성 안내·이름/익명 설정, 3) 요약 확인과 첫 보기 방식 선택 순서다. 긴 기능 튜토리얼을 강제하지 않는다. 필수 입력은 공백을 검사하고 이전 단계로 돌아가도 초안을 유지한다. 운영 화면을 열면 샘플 답변과 이름 예약을 제거하고 새 질문 하나, 답변 0개, 접수 OFF로 시작한다. 빈 결과 영역에서 운영자는 `답변 접수 시작`을 바로 실행할 수 있다. 모든 화면 설정과 글꼴은 준비 후에도 바꿀 수 있다.

운영 화면 순서는 접수 → 접수 시간 → 반응과 정렬 → 질문과 작성 안내(새 질문 포함) → 이름과 익명 → 행사 디자인 → 발표 글꼴 → 기록 다운로드다. 앞의 세 항목은 행사 중 조작, 다음 두 항목은 참여 내용과 규칙, 디자인·글꼴은 보조 설정이다. 글꼴 미리보기는 선택한 글꼴 이름, 제목·본문 견본을 담은 상자로 표시한다. 라이선스는 상자 밖 별도 접기 항목으로 둔다.

현재 첫 사용 과정은 이 시안 안에서 동작한다. 새 행사 저장, QR 발급, 다른 기기 참여 및 다시 방문했을 때의 실제 행사 복원은 서버 연결 후 구현 대상이다. 입력 검증, 단계 이동과 초안 보존, 샘플 제거, 접수 대기 및 시작 동작을 DOM 모델에서 확인했다.

## 접수 시간 일시정지와 재시작

접수 시간 조작은 `접수 시작`, 실행 중 `일시정지 / 처음부터`, 정지 중 `계속하기 / 처음부터`로 구분한다. 일시정지는 남은 시간을 밀리초로 보관하고 답변 접수도 멈춘다. 참가자·발표 화면에는 멈춘 남은 시간과 `접수 일시정지` 상태를 표시하며 작성 중인 답변은 유지한다. 계속하기는 보관한 시간으로 새 종료 시각을 계산한다. 처음부터는 입력한 분·초 전체를 사용해 바로 다시 접수한다. 답변 기록은 삭제하지 않는다.

`타이머 초기화`는 설정 분·초를 0으로 지우고 남은 시간·일시정지·종료 표시를 제거하며 제한 시간 사용을 끈다. 답변 접수 ON/OFF, 기존 답변, 작성 중 초안은 유지한다. 접수 중에는 시간 제한 없이 계속 받고 정지/마감 중에는 닫힌 상태를 유지한다. 전체 시간으로 다시 세는 목적은 `처음부터`가 담당한다. 초기화 후 시간을 다시 쓰려면 분·초를 입력하고 시작한다. 시간이 0이 된 이후 일시정지로 되살릴 수 없고 처음부터 다시 시작해야 한다. 새 질문/행사 또는 제한 시간 해제 시 정지 잔여시간도 제거한다. 조작은 운영자에게만 허용한다. 동결·이어가기·재시작·만료 경계·권한·초안 보존을 DOM 모델로 검증했다.

해·달 스위치는 첫 시작 화면과 모든 행사 준비 단계 상단에도 제공한다. 준비 중 선택한 밝기는 단계 이동과 운영 화면 진입 시 유지한다.

## 여러 질문 확장 제안 — 아직 미구현

한 행사는 N개의 질문을 보유하고 진행형 행사에는 현재 공개 질문 하나를 둔다. 질문은 준비/진행/마감 상태를 구분한다. 질문 추가는 준비 목록에 추가하는 동작이고 참가자에게 공개하는 동작과 분리한다. 현재 질문이 접수 중일 때 다른 질문을 선택해도 즉시 전환하지 않고 질문 상세 확인 후 `이 질문 진행하기`를 통해 명시적으로 바꾼다. 공개 전환은 기존 질문을 마감하고 새 질문은 접수 대기로 시작한다. 기존 답변과 질문별 제한 시간은 보존한다.

운영자 왼쪽 상단에 `질문 목록 1/5`와 `＋ 질문 추가`를 상시 제공한다. 각 행에는 질문 요약과 준비/진행/마감 상태를 표시한다. 현재 질문과 접수 조작은 이어서 배치한다. 행사 준비 두 번째 단계에서도 질문을 하나 입력한 뒤 `질문 추가`를 선택해 여러 개를 미리 준비할 수 있게 한다. 발표/참가자 화면에는 현재 질문 번호와 총 질문 수만 표시한다.

학습·퀴즈 확장은 진행자가 질문을 함께 넘기는 진행형과 참가자가 각자 답하는 자율형을 나눈다. 자율형은 질문별 작성 초안·제출 상태와 이전/다음 이동이 필요하다. 정답이 있는 퀴즈는 질문 유형·선택지·정답·해설·채점 기준을 추가해야 하며 기존 의견 수집의 진행 완료와 정답 여부를 구분한다. 기존 View 선택은 질문 유형이 아닌 답변 표시 방식이다. 이 절은 구조 제안이며 현재 단일 공개 질문 시안에 구현된 기능으로 간주하지 않는다.

## 익명 설정과 이름란 제목 분리

행사 준비와 운영자 설정에서 이름 입력란 제목을 익명 설정보다 먼저 배치한다. 익명을 켜도 이름란 제목은 수정 가능하며, 참가자 작성창은 이 제목을 그대로 사용한다(예: 작성자, 닉네임). 익명 여부는 동물 닉네임 자동 채우기만 결정한다. 이름 입력 예시와 필수 입력 설정은 익명 모드에서 적용되지 않아 비활성화 상태를 유지한다. 익명 전환으로 제목을 덮어쓰지 않으며 수정한 제목은 설정 적용 후 참가자에게 반영한다. 제목 유지·편집·참가자 표시·자동 닉네임 동작을 DOM 모델로 확인했다.

## 고양이 달리기와 샘플 복귀 보완

달리기는 네 프레임의 고양이·쥐 장면으로 변경한다. 평소 한 주기는 800ms, 남은 시간이 60초 이하이면 400ms로 빨라진다. 일시정지는 잠자는 그림으로 바꾸지 않고 CSS animation-play-state로 현재 달리기 프레임을 그대로 정지하며 속도 설정도 보존한다. 계속하기는 같은 애니메이션을 이어간다. 종료 시에만 쉬는 그림을 표시한다. 움직임 줄이기에서는 한 프레임만 정지 표시한다.

샘플 행사의 `처음 설정으로` 버튼은 운영자 GNB에 배치한다. 참가자·발표 미리보기에서는 검토 막대에 같은 복귀 동작을 제공한다. 기존 행사 답변을 초기화하는 버튼이 아니라 샘플에서 행사 준비 첫 단계로 돌아가는 버튼이다. 60초 경계·정지/재개·종료 상태와 복귀 경로를 DOM 모델로 확인했다. 실제 애니메이션의 외관은 별도 확인이 필요하다.

## 참가자 QR 및 GitHub Pages 공유

운영자 공개 화면 위에 참가자 QR·링크와 발표 링크 복사를 제공한다. 공유 주소 설정에 HTTPS 배포 주소를 지정하며 실제 독립 페이지에서는 현재 주소를 기본으로 사용한다. 같은 사이트의 `?e=행사코드&v=p` 및 `?e=행사코드&v=s`를 사용하고 별도 외부 URL 단축 서비스에 보내지 않는다. QR은 MIT qrcode-generator 1.4.4로 기기 안에서 생성하며 4모듈 흰 여백을 두고 PNG로 저장한다. 참가자 상단에는 같은 행사 참가자 링크 복사를 둔다. 클립보드가 차단되면 선택 가능한 주소를 표시한다.

독립 배포 파일은 src/seminar-board.html에서 빌드하는 public/index.html이며 공개 행사 설정은 public/event-config.js에 보관한다. 질문·이름·브랜딩·보기 설정만 포함하고 답변·운영자 비밀값은 내보내지 않는다. 업로드 글꼴은 세션 전용이라 공유 시 기본 글꼴로 대체된다. 공개 역할 링크는 해당 화면으로 직접 진입하며 시안의 역할 전환을 숨긴다. 이는 운영자 인증을 대체하지 않는다. 없는 행사 코드는 오류 안내 화면을 표시한다.

정적 파일 배포는 실시간 공유를 제공하지 않는다. 실제 행사 운영에는 관리형 백엔드·권한 정책·원자적 이름 예약과 투표 업데이트가 추가로 필요하다. 현재 생성/수정한 공개 설정을 다른 기기에서 열려면 파일을 다시 배포해야 한다. 자세한 순서와 검증 한계는 docs/github-pages.md에 기록했다.
